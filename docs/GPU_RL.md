# RL без MPC на відеокарті (гілка `gpu-rl`)

Мета: агент-нейронка без MPC, натренований на мільйонах ігор, що обганяє `mpc` (на 9001: Small 0.694 × 64,
Full 0.428 × 8 / 0.392 × 16). Спільний план — [PLAN.md](../PLAN.md), числа — [experiments/LOG.md](../experiments/LOG.md).

## Де ми (2026-10-08)

| **Full × 16** | **0.6179** | 0.3916 | **+0.226** | +0.154 … +0.307 |

Найкраща мережа: `outputs/gpu_es/2026-10-08_08-56-35/policy_best.pt` (вона ж в `agents/gpu_rl`). ES на ній вийшла на
плато (2.5 год: +0.01 до середнього).

## Що показала діагностика (2026-10-08)

- **Full:** увесь виграш `gpu_rl` над MPC — енергія (`shed` −645 млрд $ на епізод, 4 еп.); у решті статей він трохи
  марнотратніший (мита, фрахт, переповнені склади → `disposal`, `holding`: разом ~+90 млрд $).
- **Small:** енергія вже майже ідеальна (епізод 0: `shed` 2 264 млрд проти 2 238 в ідеальному плані), а **нестача
  чипів — на рівні наївного правила** (1 232 проти 1 242; ідеальний план 900, MPC 1 169). Увесь відрив від ідеалу й від
  MPC на Small — доставка чипів на ринки (ланцюг пластини → заводи → OSAT → ринки).
- Агент не бачить того, що для цього потрібно: мит на маршруті, місткості складів, незавершеного виробництва, прогнозу
  попиту, втрат попиту на конкретному ринку.

## План

1. **Нові ознаки — до PBT.** Причини: діагностика прямо називає, чого бракує, тож це дешевше, ніж шукати перебором;
   PBT обирає лише серед ознак, які вже існують; і нові ознаки можна додати, не втрачаючи навченого (див. нижче).
   - Ознаки маршруту:
     - **мито** на маршруті для його товару (ставка × цінність товару / його ціна за звичайним планом) — проти зайвих
       мит;
     - **вільне місце на складі призначення** (місткість − запас) / масштаб — проти переповнення й утилізації;
     - **незавершене виробництво**, що вийде на склад відправлення / призначення найближчими тижнями (заводи, OSAT) —
       ланцюг чипів;
     - для маршрутів до ринків: **втрачена частка попиту саме цього ринку** минулого тижня і **прогноз попиту** на
       найближчі тижні;
     - **оголошені санкції** на маршруті (`pending_prohibitions`: чи і через скільки тижнів його заборонять);
     - для пального: **запас пального на електростанції** призначення відносно її споживання;
     - можливо, **очікуваний кінець закриття протоки** на маршруті (`closure_end`).
   - **Ознаки «сусідства»** (маршрут зараз не бачить інших маршрутів — кожен вирішує сам, тож кілька маршрутів до одного
     складу можуть разом перевезти; діагностика це й показує: зайві `disposal`, `holding`): **весь вантаж у дорозі до
     складу призначення** з усіх маршрутів; **сумарна місткість інших відкритих маршрутів** до того самого складу;
     **скільки маршрутів тягнуть із того самого складу відправлення**.
   - ✅ Зроблено 2026-10-08: перші шість (мито, вільне місце, виробництво за 4 тижні, втрати і прогноз попиту на ринку,
     оголошена заборона; `closure_end` у режимі `standard` не показується — відпав); звірка «спостереження = симулятор»
     до 4e-7 на Small і Full; агент читає і стару (25), і нову (31) мережу.
   - Прогноз попиту, оголошені санкції, кінець закриття, попередження й новини створює інформаційний шар гри
     (`information.observe.wrap`, режим `standard`), якого в GPU-симуляторі нема. Але від дій агента вони не залежать
     (лише від сценарію), тож їх не треба відтворювати на GPU: один раз прогнати кожен сценарій у справжній грі на CPU,
     записати ці поля по тижнях у кеш сценаріїв і підставляти в тренуванні.
   - Друга черга: фрахт і воєнні ризики, стан заводів (R, cap_eff) і OSAT; попередження й новини (перевіряли: закриття
     майже не передбачають, AUC 0.56; і їх важко стиснути в кілька чисел про маршрут).
   - Чому не всі ознаки одразу: повне спостереження — тисячі чисел різної довжини на різних картах (мережа з фіксованим
     входом на обох картах їх не прийме); кожну ознаку треба реалізувати двічі (симулятор і агент) і звірити; більше
     входів — більше ваг, повільніший ES і більше шуму.
   - **Як не втратити навченого:** нові ознаки додаються в кінець входу, а їхні ваги в першому шарі починаються з нуля —
     мережа спершу грає точно як `gpu_rl` і далі вчиться використовувати нове (ES або PPO з `policy_best.pt`).
   - Кожну нову ознаку — у симулятор (`rl.features`) і в агента (`agent.py`) однаково, звірка `gpu_agent_check.py`.
   - Порівняння: ES з однаковим стартом, бюджетом і епізодами — старий вхід проти нового; рішення за 9001.
2. **PBT** поверх кращого методу (зараз ES): популяція (наприклад, 8) з різними «генами» — маска ознак (нулі, щоб ваги
   копіювалися), sigma і lr для ES (або lr і шум для PPO), ширина мережі; кожні N хвилин перевірка на однакових
   епізодах окремого root (**9002**, не 9001), найгірші копіюють ваги найкращих і мутують гени. Покаже, які з нових
   ознак і налаштувань справді допомагають, і дотисне плато.
3. **Гібридний агент для фіналу**: один `agent.py`, що за `config["static"]["instance_id"]` вибирає найкращого на
   кожній карті — зараз на Small `mpc_residual` (9001 × 64: 0.712), на Full `gpu_rl` (9001 × 16: 0.618). Дозволено
   правилами (агент лише читає опис гри зі `config`). Коли `gpu_rl` наздожене на Small — один `gpu_rl` на обох.
4. **Мережа, що «дивиться на сусідів»** (графова): кожен маршрут рахує свій опис, маршрути з одним складом
   призначення / відправлення обмінюються усередненими описами, потім рішення — маршрути узгоджуються між собою. Нові
   ваги обміну з нуля → старт = нинішня мережа. Окремий експеримент після PBT (або як ген PBT).
5. Ширша мережа (128) — разом із новими ознаками, якщо 64 виявиться тісною.

Застереження: відбір агентів робити на окремому root, щоб не підігнати 9001; на Full 9001 — лише 16 епізодів;
оперативна пам'ять WSL ~6 ГБ (VS Code через Remote-SSH сам бере ~2.6 ГБ — під час тренування краще консоль або
вимкнений Pylance; найнадійніше — `.wslconfig` з більшим лімітом).

## Команди

```bash
uv run python examples/gpu_check.py --task=small --episodes=6          # звірка симулятора з пакетом
uv run python examples/gpu_scenarios.py --small=1024 --full=128        # сценарії + еталони (раз на root)
SBF_MLFLOW=0 nohup uv run python examples/gpu_ppo.py --minutes=360 --pool_small=1024 > outputs/gpu_ppo.log 2>&1 &
SBF_MLFLOW=0 nohup uv run python examples/gpu_es.py --start=<policy.pt> --minutes=240 > outputs/gpu_es.log 2>&1 &
uv run python examples/watch_training.py --runs=outputs/gpu_es/<run>   # живий графік
uv run python examples/gpu_export.py --policy=<policy_best.pt>         # в agents/gpu_rl
uv run python examples/gpu_agent_check.py --task=small --episodes=3    # агент = симулятор
uv run sbf compare gpu_rl mpc --task=full --entropy=9001 --episodes=16 --n_jobs=3
uv run python examples/compare_costs.py --a=gpu_rl --b=mpc --task=small --episodes=16
```
